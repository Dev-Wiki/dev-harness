# 产品功能清单维护

用于首次盘点已经实现的功能、每次交付后的增量同步，以及反复全量复核。核对“当前支持什么”，不执行代码质量审计，也不从看板完成状态推断支持情况。

## 选择环节

| 用户目标 | 环节 | 核对范围 |
|---|---|---|
| 没有清单，希望知道已经支持什么 | 首次全量盘点 | 当前产品的全部功能范围 |
| 新功能、fix 或支持条件发生变化 | 日常增量同步 | 本次改动及受影响的现有功能项 |
| 已有清单，希望重新全量扫描、查漏或定期核对 | 全量复核 | 全部功能范围及清单中的全部既有 ID |

复用已有同类清单。用户仅询问支持情况时只读回答；明确要求盘点、同步或复核后才写入文档。

## 一份清单，两层阅读

正文面向普通用户和 PM，说明功能名称、能完成的事情、支持状态、适用范围、使用限制、可用版本和使用入口。按实际使用场景分类；分类导航只链接功能记录，不复制变化中的支持状态。

稳定 ID、验证方式、代码或测试证据、工程约束留在同一项的可展开区域。渲染器不支持折叠时使用同项下的技术详情小节。不要另建一份需要人工同步的 PM 清单。已有语种和有效格式优先，不为套模板强制改写全文。

## 首次全量盘点

1. 确认唯一文档根和清单路径。读取当前 Context、文档入口、已有功能说明和真实实现入口；计划、CHANGELOG、菜单与测试名称只作为调查线索。
2. 建立本轮基线，记录分支、HEAD 和影响产品支持的已有未提交修改。逐文件指纹和过程日志留在临时工作区或既有验证记录；清单只保留简短说明和证据链接。核对期间发生范围外变化时先对齐，不能用旧证据确认新版本。
3. 从用户任务、角色、平台、集成和运行方式列出产品范围，先列完范围再逐块核对。明确排除范围及原因；用户要求全项目却只检查部分范围时，结论必须是未完成。
4. 沿真实入口、实现与适用的测试或运行验证确认独立行为。拒绝、禁用和未接通的路径不算已支持。代码证据、契约证据、自动化测试、实际运行和目标环境验证分别记录；未执行的验证不得写为本轮通过。
5. 为已确认功能分配稳定 ID；证据不足的候选保留待确认 ID 和缺口，不进入已支持统计。独立功能计一次，适用条件和实现细节不重复计数。
6. 写入功能记录和最近一次全量盘点的覆盖记录，建立文档中心入口，分别计算当前开发版本与最新发布版本的数量。

## 日常增量同步

顺序为“实现与验证通过 → 核对文档影响并完成必要更新 → 记录结果 → 任务完成与归档”。只更新本次被证据证明的事实。

| 改动 | 清单处理 |
|---|---|
| 新增独立功能 | 查重后分配新 ID，区分开发版与已发布版 |
| 修改支持范围、行为或限制 | 更新原 ID 的说明、状态、版本和证据 |
| fix 恢复既有承诺行为 | 核对原说明及证据，通常复用原 ID；无需改正文时说明依据 |
| 内部重构、测试调整等 | 核对对外行为及证据引用，不能只凭提交类型判断无影响 |

完成记录只保存清单路径、相关 ID、结果、依据及验证入口。结果为：

- 已更新（`updated`）：必要修改已写入清单，证据与汇总已核对。
- 无需更新（`no-impact`）：已检查现有清单，说明为何不改变支持事实或证据；只填写“无影响”不构成依据。
- 不适用（`not-applicable`）：项目没有需要维护的清单或同类功能文档，说明判断依据；已有清单时不能借此跳过。

尚未检查、证据不足或必要修改不在授权范围时，记录缺口并停止成功收口。Planning 在任务就绪前把文档路径和检查要求纳入范围、验收与验证方式；Runtime 按冻结范围执行，不得自行扩权。旧任务缺少要求时先返回规划补齐。结果写入任务的验证证据或完成验收结果，不在 Dashboard 另建功能状态表。Auto Fix 的 `DocumentationCheck` 还须绑定最终改动指纹；后续改动后重新核对。

上述任务包要求仅适用于已有 Planning / Runtime 执行任务。用户直接请求文档盘点或增量同步、且没有执行包时，在本次结果或既有验证记录中说明处理依据即可，不为此强制创建规划任务。

## 可反复执行的全量复核

1. 保留现有 ID、支持记录与本轮开始前的清单快照。重新建立基线和产品范围；同时调查实现中的功能范围与已有清单，不能只复查旧行而漏掉新模块。
2. 每个范围记录实际检查入口、证据和“已检查 / 待检查 / 受阻”结果。恢复盘点先核对基线；未变化的范围可复用仍然有效的证据，变化的范围重新验证。
3. 每个既有 ID 必须有结论：保持、更新、转待确认、已弃用或已移除。新行为查重后才新增 ID；名称、分类和适用条件变化不自动产生新功能。
4. 找不到旧功能时先检查入口迁移、改名、开关和替代实现。不能证明移除时转待确认，保留原 ID 与旧依据；只有当前实现或明确移除事实证明不再支持时，才标为已移除，并保留 ID 的简短记录。
5. 汇总新增、变化、转待确认、已弃用和已移除的 ID。未变化的再次复核不得增加重复项、重新编号或凭扫描日期改变版本归属。
6. 只有全部声明范围已检查、所有旧 ID 有结论、未决项已列出、计数和链接已核对、基线未漂移，才能记录“全量盘点完成”。范围受阻或尚未检查时保留之前的最近完整盘点记录，并明确本轮未完成；单个候选证据不足可以列为待确认，不能计为已支持。

清单只维护最近一次完整盘点的基线、覆盖范围和简短结果；历史由 Git 或已有验证记录保存。临时进度保存在既有工作记录或临时文件中，不新增第二份功能权威文档，不按扫描次数追加整份副本。完成全量盘点表示按声明范围核对，不保证穷尽任何未知功能。

## 完成检查

- 全量盘点有基线和覆盖证据；每个既有 ID 均有结论，新项已查重。
- 增量同步有明确结果、依据和必要更新；任务验收或 Auto Fix 完成门禁包含该检查。
- 正文说明用途、支持程度、限制和入口；同项下保留工程核验信息。
- 待确认和已移除不计入已支持总数，已弃用单独统计；开发版与发布版分别统计，不用 Git 标签自动证明已发布。
- 引用真实文件、稳定章节或测试方法，避免继续维护易漂移的固定行号；未执行的测试不标为本轮通过。

这些规则约束 Agent 的功能盘点工作，不提供静态代码自动识别全部产品功能的保证。
