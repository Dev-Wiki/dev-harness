## 维护规则

- 首次全量盘点建立清单；日常增量同步跟随功能和 fix；全量复核重新核对全部功能范围及所有既有 ID。
- 每个可独立验证的功能项只分配一个稳定 ID；功能分类、页面、路由、API、模块、任务和测试本身不单独计数。
- 平台、角色、版本和部署方式差异写入适用范围；状态、范围、名称、版本或证据变化保留原 ID。
- “支持状态”“适用范围”“版本归属”和“验证方式”必须分别记录，不能互相替代。
- 普通用户说明与技术证据属于同一个功能项，不维护另一份需要人工同步的清单。
- 增量同步记录“已更新 / 无需更新 / 不适用”及依据后再收口，不能用任务完成状态证明已支持。
- 全量复核完成前核对覆盖范围、旧 ID 去向、计数、链接和基线；未完成时保留之前的完整盘点记录。
- 只保留最近一次完整盘点摘要，历史由 Git 或已有验证记录保存；未来工作写入规划文档，已发布变更写入 CHANGELOG。
