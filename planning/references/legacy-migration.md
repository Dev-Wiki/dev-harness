# 旧版单体计划迁移

仅当既有 `TaskDetails.md` 超过 Planning 容量护栏，或用户要求拆分任务、归档历史时，读取本参考。

迁移必须保留每段任务正文和每条有意义的链接。目标是缩短活跃读取路径，而不是通过摘要丢弃历史。

## 1. 迁移前检查与映射

编辑前按标题盘点单体文档。建立覆盖整个源文件的迁移台账：每段任务正文一行；前言、分组说明、共享验证基线、维护规则等非任务区间也分别占一行。

| 字段 | 必须确认的内容 |
|---|---|
| 任务编号（Task ID） | 保留既有稳定编号；出现重复或缺失时停止迁移。 |
| 源区间 | 一项任务到下一个同级或更高级标题前结束，文件末尾（EOF）也可作为边界。非任务区间单独登记，确保每一行都有归属。 |
| 原始状态 | 在状态语义得到证据确认前，原样保留项目本地值。 |
| 完成证据 | 记录用户明确给出的状态，或实现与验证证据。 |
| 里程碑 | 只采用源文档中的明确元数据，不根据任务顺序或名称推断。 |
| 完成日期 | 只采用明确日期。 |
| 目标位置 | 为正文选择唯一的活跃或归档路径。 |
| 出站链接 | 盘点正文中的相对链接和同文件锚点。 |
| 入站链接 | 在整个仓库中搜索指向源文件或任务锚点的链接。 |

逐项确定非任务区间的归属：

- 当前里程碑目标、范围或覆盖摘要 → `Dashboard.md`；
- 活跃工作顺序、共享依赖、验证基线或维护规则 → 精简后的 `TaskDetails.md`；
- 整个里程碑的最终证据或历史摘要 → 对应归档目录的 `README.md`；
- 具有独立生命周期的专题正文 → 项目自己的专题文档，并从合适的索引链接过去。

不得把后续更高级的共享章节并入前一项任务；前言、有实际含义的分隔内容和全局章节即使没有任务编号，也不得丢弃。

搜索仓库所有自有 Markdown 和规则文件，不要只查 `plan/`：

```bash
rg -n 'TaskDetails\.md(?:#[A-Za-z0-9._~!$&()*+,;=:@%/-]+)?' . \
  --glob '*.md' --glob '*.mdc' --glob '!vendor/**' --glob '!node_modules/**'
```

移动文件前，报告台账总数、源文件完整覆盖情况、歧义、拟定路径和入站链接影响。任务边界、重复编号、内容归属或完成状态无法安全确定时停止，并保留全部源内容。

## 2. 确定性分类

- 只有完成状态符合项目证据要求，或用户明确确认完成时，任务才能归档。
- “已实现”“部分完成”“待部署验收”等含糊状态保持活跃，除非项目明确把它们定义为完成。
- 没有明确里程碑但符合归档条件的任务，放入 `archive/legacy-import-YYYY-MM-DD/`。必须说明这是迁移归集目录，不是推断出的产品里程碑。
- 最近完成摘要只按明确的完成日期排序。缺少日期的任务不进入 Dashboard 最近五项，改为链接对应归档索引。
- 规划中、进行中、受阻、状态有歧义及远期任务迁入 `tasks/<Task-ID>.md`。
- 有充分完成证据的任务直接迁入 `archive/<milestone>/<Task-ID>.md`，不要先经过 `tasks/`。

## 3. 应用前暂存

把大范围迁移视为针对移动映射中精确路径的一次事务：

1. 记录所有可能变更文件的迁移前哈希或逐字节快照，保留工作区中无关的既有修改。
2. 在正式文档树之外的临时暂存目录生成完整目标树和拟改文件；校验相对链接时按文件最终路径解析。
3. 用暂存树和仓库未变文件共同校验源内容覆盖、任务编号归属、目标数量、已改写入站链接和相对链接目标。
4. 所有暂存后置条件通过后，才把已验证的移动映射应用到正式目录。
5. 在正式目录重复运行相同后置条件。应用或最终校验失败时，只从快照恢复移动映射涉及的路径，并只删除本次迁移新建的文件。报告失败前，确认计划文件和入站链接文件恢复到迁移前哈希。

回滚时不得使用宽泛的 Git reset 或 checkout，也不得覆盖用户的无关修改。

## 4. 无损分段迁移

分段处理单体文档，但每条任务与非任务台账记录必须且只能处理一次：

1. 把完整源任务正文复制到目标文件，包括最终原因说明和证据。
2. 只规范 `Task.template.md` 所需的外层任务标题或元数据；不得仅为套用模板而重写业务内容。
3. 把同文件任务锚点改为新的任务文件或归档文件路径。
4. 按目标文件目录重新计算迁移正文中的每条相对链接，包括指向 `Dashboard.md`、`topics/`、`projects/`、需求、产品文档、图片和同级归档的链接。
5. 更新迁移前检查中发现的所有仓库自有入站链接，保留有意义的链接文字和锚点。
6. 把每段非任务内容放入已映射的当前索引、归档索引或独立专题文档。
7. 把活跃任务加入 `TaskDetails.md`，把完成任务加入选定的里程碑归档索引。
8. 只有每条台账记录都有已验证的暂存目标后，才用精简活跃索引替换单体正文。

不得在单体文档和目标文件中重复保留同一正文；迁移前文本由 Git 历史保存。

## 5. 重新打开任务

归档任务文件是不可变的收口快照。任务重新打开时：

1. 保持 `archive/<milestone>/<Task-ID>.md` 和归档索引条目不变；可以补一条指向重新打开任务的链接。
2. 创建 `tasks/<Task-ID>.md` 作为唯一活跃权威文件，并链接此前的收口快照。
3. 记录重新打开的原因、新范围和当前验收标准。
4. 任务未关闭期间，Dashboard 和 `TaskDetails.md` 只链接活跃任务文件。

## 6. 后置条件

删除单体正文或宣布成功前，必须逐项确认：

- 源任务数量等于活跃任务文件数加上新建归档快照数；
- 每段任务和非任务源区间只出现在一个目标中，没有遗漏或重复；
- 每个活跃任务编号只有一个活跃权威文件；
- Dashboard 和 `TaskDetails.md` 只保留有界索引与链接；
- 每个归档索引目标都存在；
- 仓库自有入站链接不再指向已移除的 `TaskDetails.md` 锚点；
- 每条改动过的 Markdown 相对链接都能解析到现有文件和有效锚点；
- 明确报告含糊状态、缺失日期和 legacy-import 归集目录分配；
- `git diff --summary --find-renames` 与最终移动映射一致。

暂存校验失败时，不得修改正式计划。正式应用失败时，恢复移动映射涉及的路径并核对迁移前哈希。报告造成阻塞的台账记录，不得留下半迁移状态。
