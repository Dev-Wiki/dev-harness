# BUGFIX_GUIDE

用于沉淀项目的 bugfix harness 输入格式，降低 AI 与人工在复现和定位阶段的上下文装载成本。

## 1. Bug 描述模板

每个 bug 至少记录以下字段：

- **标题**：一句话描述问题
- **现象**：实际看到的报错、异常行为、日志或截图
- **预期**：正确行为是什么
- **影响范围**：影响哪些接口、页面、模块、用户或环境
- **首次出现时间**：可选，但推荐记录

## 2. 最小复现信息

优先记录最小必要信息，不要把无关步骤混进来：

- **环境**：版本、系统、设备、网络、开关、账号
- **前置数据**：fixture、种子数据、依赖服务状态
- **复现步骤**：按顺序列出最小步骤
- **复现命令**：能命令化就优先给命令
- **实际结果**：包括错误码、日志、截图、trace id

## 3. 调用链记录方式

定位过程中，至少沉淀以下信息：

- **入口**：接口、事件、任务、按钮、定时器或消费者
- **关键调用链**：只记录导致问题的主干路径
- **关键状态**：输入、输出、分支条件、异常点
- **缺失观测**：哪些日志、断言或埋点还不够

建议记录成固定结构：

```text
EntryPoint:
CallChain:
ObservedSignals:
MissingObservability:
RootCauseCandidates:
```

## 4. 回归测试落点

每次修复至少回答这 4 个问题：

1. 这个问题最适合落在哪层验证：`quick`、`bugfix` 还是 `full`
2. case 应该放在哪个目录或模块
3. 样本或 fixture 从哪里来
4. 哪个断言真正证明问题被修复

## 5. 完成定义

一个 bugfix harness 至少满足：

- 有最小复现输入
- 有调用链或根因证据
- 有回归测试落点
- 有可执行验证命令
- 有失败时最少记录标准
