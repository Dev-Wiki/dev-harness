# HARNESS 构建与验证契约定义调整

## 目标

明确 `HARNESS.md` 是项目构建、验证和执行环境约束的唯一事实源，并确保所有原生识别 `AGENTS.md` 的 AI Agent 在执行构建、测试或验证前读取该文件。

## 范围

- 更新 `context/templates/HARNESS.template.md`，增加正式定义和适用边界。
- 更新 `context/templates/AGENTS.template.md`，增加强制读取、禁止猜测和冲突优先级规则。
- 更新 `docs/HARNESS_GUIDE.md`，使用户指南与模板定义一致，并校正已过时的流程描述。
- 更新 `tests/test_context_cli.py`，验证生成文件包含新契约定义和强制引用。

不修改构建命令探测算法、现有模板字段、CLI 参数、其他 README 或安装行为。

## 契约定义

`HARNESS.md` 的正式名称为“项目构建与验证契约”。它记录：

- 项目类型与可执行环境；
- build、quick、bugfix、full 命令；
- 编译启动诊断；
- 高风险目录与禁改区域；
- 自动识别候选与人工确认项。

其中命令映射和执行环境以 `HARNESS.md` 为唯一事实源；行为、安全和修改边界以 `AGENTS.md` 为准。

## AGENTS 强制导航

生成的 `AGENTS.md` 在项目上下文之前增加“构建与验证契约（AI 必读）”章节，要求 Agent：

1. 在执行构建、测试或验证命令前读取根目录 `HARNESS.md`；
2. 不得根据 README、CI 配置或生态经验覆盖、替换或猜测契约命令；
3. 遇到 `Unknown` 或 `Missing` 时停止猜测并提示补齐；
4. 按职责处理冲突：行为与安全规则服从 `AGENTS.md`，命令和环境服从 `HARNESS.md`。

该要求不强制所有纯阅读任务预加载 `HARNESS.md`，避免无关任务消耗上下文。

## 兼容性与失败处理

- 文件名和现有章节字段保持不变，已有下游工具无需迁移。
- 自定义仓库模板仍可覆盖内置模板；只有采用新版内置模板或同步自定义模板的仓库会得到新定义。
- `HARNESS.md` 缺失、不可读或关键命令未知时，Agent 不得臆造替代命令，应向用户报告契约不完整。

## 测试

先在上下文 CLI 测试中加入新断言并确认失败，再修改模板使测试通过。最后运行完整测试套件，确认安装打包和上下文生成行为没有回归。
